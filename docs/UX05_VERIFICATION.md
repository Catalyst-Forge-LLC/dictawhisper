# UX05 capture and processing visibility — verification

2026-10-05. **Verified.** Next implementation packet: UX06 MayDo review and resilient backfill. Physical touch / actual browser zoom review remains the separate UX02-V01 item.

## Delivered behavior

- Header capture stays compact. Record requests permission only after a click. Stop produces a retained draft with native playback, Save, Download, Discard, and Record again. Save requires an explicit server acknowledgment. Failed and unacknowledged saves retain the same Blob and upload identity. Closing a live recording offers Keep recording or Stop and review; an outstanding microphone request can be cancelled. Page teardown releases hardware and never uploads; leaving with unsaved audio triggers the browser's loss warning.
- Import supports multiple files and window file drops without shifting the entry layout. Each file has Preparing, Uploading, Saved, or Failed state, with its own recovery action. Only two upload requests run concurrently. Failed rows retain the source File. Supported containers and the 80 MiB limit come from the server. Uploads inspect container signatures independently of extension, use exclusive writes with collision suffixes, and preserve the original filename in Activity and the eventual sidecar. Container acceptance acknowledges saved bytes; the subsequent audio probe can still reject corrupt or unplayable content.
- Stable upload IDs have a receipt lookup. The client checks it before sending a retry. The server returns the existing acknowledgment for repeated IDs; existing audio and sidecars are never overwritten by imports. Retained upload receipts are exempt from completed-history pruning.
- Activity is driven by settle deadlines and actual queue processor callbacks: waiting, queued, transcribing, queued cleanup, cleaning, ready/original-only, individual failures, and interrupted work. Its durable JSON lives in an internal `.dictawhisper` directory beside the configured index directory. Internal history and replacement transcript files are excluded from journal scanning. Unfinished work becomes Interrupted after restart and requires explicit recovery; watchers do not silently replay it.
- Snapshot/event epoch and revision checks repair missed updates; reconnect refreshes authoritative status. The open drawer also refreshes cheaply every five seconds. It shows current work, failures with targeted retries, the latest five completed entries, expandable earlier completions, existing bulk-job progress, and on-demand System status. Bulk-job persistence and resumable backfill remain UX06.
- Opening saved audio before its sidecar exists shows a pending reader and native player. It does not request a nonexistent transcript. Reconciliation preserves entry identity, selection, reader scroll, and paused playback position. Opening a saved entry closes the capture panel. Reading and copying remain available during cleanup and disconnected periods; writes wait for connection.
- Retries join existing transcription/cleanup work. Cleanup retry never invokes transcription. Retranscription writes a replacement before installing it and preserves the current human title, star, edited tags, and MayDo decisions. Audio conversion updates the same Activity identity and playable path. Process now bypasses the long sync delay while retaining a two-second quiet-write guard and the normal organization path.

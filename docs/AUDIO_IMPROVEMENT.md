# Audio improvement and retranscription

Date: 2026-10-22

Scope: Shared automatic preparation for new imports, a per-entry recovery flow, and resumable library retranscription using FFmpeg with Bark Pro or faster-whisper. Bark Pro is now the default; Settings → Transcription saves a model choice without restarting. See [Bark behavior and verification](BARK_EXPERIMENT.md) for its timing/provenance contract. Other model integrations and neural denoisers remain deferred. Existing recordings are only retranscribed after an explicit batch Start or per-entry action.

## Experience

Open **Reader → More → Improve audio & retranscribe…**. This is separate from **Reprocess readable transcript**, which only reruns text cleanup.

1. Select Automatic (default), Quiet speech, Uneven volume, Background noise, or Unfiltered original.
2. Choose Bark Pro, Whisper large-v3 or turbo. This starts with the saved default but is a per-attempt setting. Whisper speech detection is an optional disclosure, off by default to include faint speech; Bark includes all audio.
3. Prepare the audio preview. Original lookup checks every supported `_original` container before using the ordinary working file. If no separate original exists, the UI identifies the available source instead of claiming it is untouched.
4. Switch original/enhanced at the same playhead. Only one player plays at a time. Recording pauses the preview.
5. Create a candidate transcript. Closing the dialog or reloading the page does not discard server work. Ready candidates appear on library cards and in a compact reader notice with **Review new transcript**. Mounted cards refresh their metadata every ten seconds while the page is visible. Reopen the original action to check running work. Progress uses actual phases, not invented percentages.
6. Compare current and candidate machine transcripts. Desktop places them side by side; phones show the new transcript first. Select **Use new audio & transcript** or **Keep current version**. If the saved version changed since preparation, review the updated comparison (including a disclosure for current readable cleanup), then explicitly **Replace reviewed version**. No new ASR run is required. Readable cleanup remains an explicit next action after acceptance.
7. Reopen the action for **Undo · restore previous version**. Undo is conditional on the accepted transcript remaining unchanged; later text/cleanup changes block automatic Undo rather than overwriting newer work. Earlier snapshots remain on disk.

The dialog uses native modal focus containment, Escape/Close, focus return to More, visible focus, native inputs, keyboard-scrollable/copyable read-only textareas, 44px action targets, and a sticky action row. A failed request keeps the attempt and offers Refresh status to reconcile an uncertain write.

## Audio contract

All presets read a private snapshot of the source and write PCM WAV. They never trim leading silence, stretch time, re-encode MP3, or alter source bytes. Duration must remain within 150ms of the source or the attempt fails. There is a 30-minute FFmpeg timeout.

| Preset | Processing | Limits |
| --- | --- | --- |
| Automatic | Measure one-second energy, active-level variation and decoded-channel peaks; choose unfiltered, quiet or uneven | Never automatically selects noise removal. |
| Quiet speech | Gain toward -22 dB median active level, limited by -1 dB peak headroom and a 30 dB boost cap | Loud peaks can limit useful gain; the preview recommends Uneven volume in that case. Near-silence gets a warning. |
| Uneven volume | `dynaudnorm=f=250:g=15:p=0.89:m=10` | Conservative peak target and maximum gain. No claim of improved recognition on every recording. |
| Background noise | 80 Hz high-pass, `afftdn=nr=8:nf=-50:tn=1`, then the same leveling | Mild steady-noise/rumble treatment; not source separation, dereverberation, or reconstruction. |
| Unfiltered original | PCM conversion only | A baseline transcription from the source without enhancement. |

Routine imports and this action share preparation and diagnostics, starting from the best available original rather than repeatedly processing an enhanced version. FFmpeg/ffprobe are required even in unfiltered mode; doctor reports both. Bark uses its separately installed local runtime; selecting a model never installs one. Older standalone scripts using the legacy `cleanAudioFile` helper are not the app's normal import path.

### Transcription context and prompt leakage

Whisper's `initial_prompt` supplies preceding transcript context, not chat-style instructions. The former default included instructions such as “Transcribe the speech accurately…”; the operator reported that prose appearing in a transcript. All app transcription paths now default to an empty prompt, including the persistent worker, one-shot fallback, and direct Python CLI. Configured `whisper.promptTerms` remain supported as a plain comma-separated vocabulary list, with no surrounding instructions. This follows Whisper's [vocabulary/context contract](https://github.com/openai/whisper/blob/main/whisper/transcribe.py).

Restart the app to load the fix and create a new transcription attempt for an affected entry. Previously generated candidates and saved transcripts are not silently rewritten; review and accept a fresh candidate through the existing recovery flow. Removing our instruction prose eliminates that injected source but does not guarantee hallucination-free recognition on weak audio. Readable-text cleanup alone cannot recover the speech missed by ASR.

## State, storage, and preservation

- Job phases: preparing → preview → transcribing → ready → applied. Discarded, failed, and reverted are explicit outcomes. On restart, unfinished jobs become retryable failures; no model runs automatically on restoration.
- Each attempt has a random UUID and is bound to a stable entry ID. Source snapshots, candidate WAV/JSON, the previous entry JSON, and job receipts live under a configured root's `.dictawhisper/audio-improvements/<id>/`. Watchers ignore this directory.
- Acceptance copies and verifies an immutable `<entry>_enhanced-<uuid>.wav` sibling before atomically selecting it and its transcript in one sidecar write. The new sidecar field is `audioEnhancement: { versionId, preset, model, appliedAt }`. A missing selected WAV is an audio error, not a silent fallback to differently timed audio.
- Enhanced siblings are excluded from independent import/indexing and included in entry move/Trash/restore bundles. UUID-based saved history continues to resolve after path changes. Confirmed permanent Trash deletion also removes that entry's hidden improvement artifacts.
- Current display title, recording identity/date, stars, tags, arbitrary unrelated sidecar fields, MayDo IDs/titles/statuses, and extraction provenance survive acceptance. Transcript-dependent cleanup and playback cues are replaced/invalidated. Existing MayDo timestamps become null because older preprocessing may have trimmed the source timeline. Quotes and decisions remain available; extraction refreshes their relationship to the new transcript.
- Baseline transcript fingerprints reject stale acceptance by default, including automatic batch replacement. Manual comparison returns a fingerprint token for the current saved version; explicit acceptance may replace that reviewed version, but checks the token both before and after the audio copy. Further changes require another review. Undo restores the exact replaced transcript-owned fields, preserving subsequent human metadata and MayDo status edits. Saved source quotes restore matching prior MayDo timings.
- Entry operation locks prevent concurrent processing/moves during a running attempt or acceptance. Whisper jobs, model switches, and one-shot fallbacks share one queue. VAD options reach both worker and fallback paths. Fallback processes have a 45-minute timeout and late worker exits cannot reset a newer worker.
- Discard removes only the known candidate artifacts; accepted history persists for recovery until confirmed permanent deletion. Lossless files and retained versions consume additional disk space.

## HTTP contract

Every operation resolves the configured watch-root allowlist and binds attempts to the requested entry. Client paths cannot choose storage destinations or arbitrary FFmpeg filters.

| Method | Path | Input/result |
| --- | --- | --- |
| GET | `/notes/audio-improvement` | `file`, optional `id`; current attempt, current text, active version, history summaries, transcription availability |

### Automatic pipeline contract (version 1)

Routine capture now uses the configured Whisper model (default large-v3) with speech gating off, instead of the old fixed silence-removal/denoise/MP3 chain. `audio.preprocess: false` selects an unfiltered working copy; it does not disable assessment or diagnostics. Originals are not overwritten. The audio selected for playback and the new transcript are published together only after successful preparation/transcription; existing versions are retained in the audio-improvement history. Normal cleanup/tags/MayDos still follow publication.

FFmpeg streams 16 kHz decoded PCM into one-second energy measurements. Auto keeps adequate audio unfiltered, raises consistently low audio with available peak headroom, or levels substantial variation. Silence is excluded from active-level percentiles. The decoded-channel imbalance and near-full-scale measures are clues, not an SNR, clipping repair, speech detector, or accuracy score. Noise reduction remains a manual preset. Working WAVs use PCM at 16 kHz, preserve channels and duration, and never trim pauses.

`transcriptionQuality` records pipeline version, model, speech-gating choice, preparation/assessment, source size/mtime/SHA-256, and review issues. Diagnostics cover empty text, invalid timing, repeated wording, uncertain Whisper segments and energetic spans with no text. Energy can be music/noise. Up to three distinct suspicious spans receive a bounded alternate pass (at most 45 seconds each, opposite VAD setting). Alternatives and errors remain attached to review issues; they are never silently stitched into the first transcript. Flags remain for human listening even when both passes agree.

### Library batch contract

`GET /tools/transcription/batch` returns counts and at most 50 result summaries (`offset`, optional `filter`); it never returns transcript bodies. `POST` accepts `preview` with `{scope:{year,selection,model}}`, then `start` with the returned `id`, `policy` (`review` or `replace_unflagged`), and optional `cleanup`. Other commands are `stop`, `resume`, `retry_failed`, and `review_result` with `candidateId`. Year is blank or four digits; selection is `outdated`, `flagged`, or `all`; model is large-v3 or turbo. Active library scope excludes Trash/staging; unavailable sources are reported.

Preview reads sidecars and source stat metadata without launching FFmpeg/ASR or rewriting entry content. Outdated means missing/different pipeline version or target model/VAD policy, an audio failure, or different source size/mtime. SHA-256 is recorded during preparation; preview intentionally does not hash the whole library. External audio edits preserving size AND timestamp are not detected by that shortcut; All entries explicitly reruns them. Original lookup prefers `_original` across containers and otherwise reports that only available audio exists. Execution rechecks source stability, identity, allowed roots, active work and candidate baseline. Moved entries can resolve by stable identity; missing/changed entries fail individually.

The saved batch manifest sits beside Activity state in `.dictawhisper/transcription-batch.json`. Checkpoints include candidate IDs before model execution. Stop finishes the current entry; restart leaves the batch Interrupted until Resume. Resume reuses finished candidates and recognizes an accepted sidecar whose batch receipt was interrupted. Completed rows are not replayed. Failed items can be retried separately. A new scope archives the previous completed manifest; candidate/history access also remains on each entry. Progress persistence failures stop further work. Model execution uses the shared serialized Whisper worker.

Review is the default. Replace unflagged is an explicit start policy: diagnostics must exist and be empty before automatic acceptance. Flags hold candidates for listening; empty/invalid candidates fail without replacing existing text. Previous raw/readable text is retained in history, and current title/tags/stars/MayDo decisions survive. Optional readable processing queues cleanup/tags/MayDos for accepted entries and reports it separately in Activity; batch completion means transcription candidates/replacements finished, not that all queued cleanup has finished. Like manual recovery, Undo is guarded against later transcript/cleanup changes; previous files remain saved even when automatic Undo is blocked.
